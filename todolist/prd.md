# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

- 문서 버전: v0.1 (설계 초안)
- 작성일: 2026-11-02
- 상태: 설계 완료 / 구현 전

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 처리 여부를 확인하며, 하루를 마무리할 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 **"오늘"에 집중하는 단순한 할일 목록**을 목표로 한다.

### 1.2 목표
- 3초 안에 할일 하나를 추가할 수 있다.
- 오늘 해야 할 일과 완료한 일을 한눈에 파악할 수 있다.
- 서버나 로그인 없이 브라우저만으로 동작한다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 유지된다.

### 1.3 비목표 (이번 범위에서 제외)
- 회원가입/로그인, 여러 기기 간 동기화
- 팀 공유, 협업 기능
- 반복 일정, 캘린더 연동, 푸시 알림
- 하위 할일(서브태스크), 첨부파일

## 2. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| 직장인 | 출근 후 오늘 업무를 정리 | 빠른 입력, 우선순위 표시 |
| 학생 | 과제·공부 계획 관리 | 진행률 확인으로 동기 부여 |
| 개인 사용자 | 장보기·집안일 등 생활 할일 | 모바일에서 간편하게 체크 |

## 3. 사용자 스토리

1. 사용자로서, 입력창에 할일을 적고 Enter를 누르면 목록에 바로 추가되길 원한다.
2. 사용자로서, 체크박스를 눌러 할일을 완료 처리하고, 다시 눌러 되돌릴 수 있길 원한다.
3. 사용자로서, 잘못 쓴 할일을 수정하거나 삭제할 수 있길 원한다.
4. 사용자로서, 중요한 할일에 우선순위를 표시해 먼저 눈에 띄게 하고 싶다.
5. 사용자로서, 오늘 몇 개 중 몇 개를 끝냈는지 진행률을 보고 싶다.
6. 사용자로서, 전체/진행 중/완료 항목을 필터링해서 보고 싶다.
7. 사용자로서, 완료한 항목을 한 번에 정리(삭제)하고 싶다.
8. 사용자로서, 어제 끝내지 못한 할일을 오늘로 가져오고 싶다.

- 모바일(< 600px): 전체 폭 사용, 좌우 16px 여백, 터치 영역 최소 44×44px
- 데스크톱(≥ 600px): 최대 폭 560px 중앙 정렬 카드형 레이아웃

- 색상은 CSS 변수(`--bg`, `--text`, `--accent`, `--muted`, `--danger`)로 정의하고 다크 모드에서 재정의
- 우선순위 색상: 높음 `빨강`, 보통 `주황`, 낮음 `회색`
- 폰트: 시스템 폰트 스택 (Pretendard 사용 시 웹폰트 로드)
- 애니메이션: 항목 추가/삭제 시 150~200ms 페이드·슬라이드

## 6. 데이터 설계

### 6.1 할일 객체 (Todo)

```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~100자
  done: boolean;         // 완료 여부
  priority: 'high' | 'medium' | 'low'; // 기본값 'medium'
  date: string;          // 'YYYY-MM-DD' (로컬 시간 기준)
  order: number;         // 정렬 순서
  createdAt: number;     // timestamp(ms)
  completedAt?: number;  // 완료 시각
}
```

### 6.2 저장 구조 (localStorage)

| 키 | 값 | 설명 |
|---|---|---|
| `todolist:v1:todos` | `Todo[]` (JSON) | 전체 할일 목록 |
| `todolist:v1:settings` | `{ theme: 'system' \| 'light' \| 'dark', filter: string }` | 사용자 설정 |
| `todolist:v1:lastVisit` | `'YYYY-MM-DD'` | 이월 기능(F-14) 판단용 |

- 키에 버전(`v1`)을 포함해 이후 스키마 변경 시 마이그레이션 가능하게 한다.
- localStorage 접근은 `try/catch`로 감싸고, 실패 시 메모리 상태로만 동작하며 안내 메시지를 표시한다.
- "오늘"은 사용자 로컬 시간대 기준 날짜로 판단한다.

## 7. 기술 설계

### 7.1 기술 스택
- **HTML + CSS + Vanilla JavaScript** (빌드 도구·프레임워크 없음)
- 이유: 기능 규모가 작고, 파일을 브라우저로 열기만 해도 동작해야 하며, 의존성 관리 부담이 없음

### 7.2 폴더 구조 (예정)

```
todolist/
├── prd.md          # 본 문서
├── index.html      # 마크업
├── css/
│   └── style.css   # 스타일, 테마 변수
└── js/
    ├── app.js      # 진입점, 이벤트 바인딩
    ├── store.js    # 상태 관리 + localStorage 입출력
    ├── render.js   # DOM 렌더링
    └── utils.js    # 날짜 포맷, ID 생성 등
```

### 7.3 아키텍처
단방향 데이터 흐름을 따른다.

```
사용자 이벤트 → app.js (핸들러) → store.js (상태 변경 + 저장) → render.js (화면 갱신)
```

- `store`는 상태(`todos`, `filter`)를 단일 객체로 보관하고, 변경 함수(`add`, `toggle`, `update`, `remove`, `clearDone`, `reorder`)만 외부에 노출한다.
- 상태가 바뀔 때마다 저장 후 `render(state)`를 호출한다.
- 목록 항목 이벤트는 이벤트 위임(목록 컨테이너 하나에 리스너)으로 처리한다.
- 사용자 입력 텍스트는 `textContent`로만 삽입해 XSS를 방지한다(`innerHTML` 사용 금지).

### 7.4 주요 함수 명세

| 모듈 | 함수 | 설명 |
|---|---|---|
| store | `load()` | localStorage에서 상태 복원 |
| store | `addTodo(text, priority)` | 유효성 검사 후 추가 |
| store | `toggleTodo(id)` | 완료 상태 반전 |
| store | `updateTodo(id, patch)` | 텍스트/우선순위 수정 |
| store | `removeTodo(id)` | 삭제 (실행 취소용 백업 보관) |
| store | `undoRemove()` | 직전 삭제 복원 |
| store | `clearDone()` | 오늘 완료 항목 일괄 삭제 |
| store | `getTodayTodos(filter)` | 오늘 날짜 + 필터 적용 목록 반환 |
| render | `render(state)` | 진행률·목록·푸터 전체 갱신 |
| utils | `todayKey()` | 로컬 기준 `YYYY-MM-DD` 반환 |
| utils | `formatKoreanDate(date)` | `2026년 11월 2일 (월)` 형식 |

## 9. 예외 및 엣지 케이스

| 상황 | 처리 |
|---|---|
| 빈 문자열/공백 입력 | 추가하지 않고 입력창 흔들림 효과 |
| 100자 초과 | 입력 제한(`maxlength`) |
| localStorage 비활성/용량 초과 | 메모리로 동작 + "저장되지 않습니다" 배너 |
| 저장 데이터 손상(JSON 파싱 실패) | 빈 목록으로 시작, 손상 데이터는 백업 키로 이동 |
| 자정이 지난 상태로 페이지 유지 | 포커스 복귀 시 날짜 재확인 후 화면 갱신 |
| 여러 탭 동시 사용 | `storage` 이벤트로 다른 탭 변경 사항 반영 |
